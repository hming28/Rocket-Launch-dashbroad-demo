## 2. F1:修 `getEngineMatrixSvg` 作用域(P-01)

**原因**:`getEngineMatrixSvg`(约第 5764 行)定义在 `Views` 这个 IIFE 内部(第 5087–6185 行),而回收视图的更新代码(约第 7598 行)在 IIFE 外面调用它。`EA`(发动机角度数组)很可能有同样问题。

**做法**

1. 把 `EA` 和 `getEngineMatrixSvg(size)` 提升到脚本顶层(与 `buildEngineMatrix` 同一层级),`Views` 内部的三处调用(约 5136、5933 行)改用顶层版本;删掉 IIFE 内的重复定义。
2. 同类检查:用脚本列出每个 IIFE 内定义、却被 IIFE 外引用的标识符(或直接执行 F1 验收里的穷举回归),一并修掉,不要只修这一个。
3. 仍然遵守「只 mount 一次」:回收视图的发动机面板在 `curT` 变化时只更新状态文字和点火台数,不要每次重写 `innerHTML`(现在每 tick 都在重写)。

**验收**:见 §8 的 A1(穷举回归)。**pageerror 必须为 0**。

### 3.2 制动余量曲线

1. **横轴** t∈\[330, 420\] s;**纵轴**高度(m),自动上限 = 该区间实际高度最大值 × 1.1。

3. **`kN = 0` 时 `h_req` 不定义**:断开曲线,不要连线、不要画到纵轴顶。该段在图里写一行灰字「滑行 · 余量未定义」。

## 4. F3:公众版时间轴标签防重叠(P-04)

**公众版节点名**:点火、升空、最大压力、一级关机、分离、翻转、返回大气层、着陆减速、着陆。节点 x 坐标仍按 `x(t) = x0 + W·t/428`,**不得为了避让改变节点位置**,只改标签位置。

**算法**(写成纯函数 `layoutLabels(nodes, measure, rows=2, gap=8)`,可单测)

1. 对每个节点,用 `measure(text)` 得到标签宽度(`canvas.measureText` 或隐藏 span,随语言重算)。
2. 按 x 从左到右,优先放第 0 行;若与第 0 行上一个标签的间距 < `gap`,放第 1 行;若第 1 行也冲突,**把标签改成缩写**(中文取前 2 字,英文取前 3 字母)再试;仍冲突则只显示圆点、标签放 tooltip 并写入 `aria-label`。
3. 标签最左/最右不得超出时间轴容器(夹紧)。
4. 两行标签区高度固定,位于时间轴线**上方**、速度/高度行**下方**,公众版时间轴区总高 64px,不得压到「下一步」那行字。
5. 语言切换、窗口缩放(resize)后重新计算。

**验收**(A3):1280×720、1440×810、1920×1080 下,公众版所有标签的 `getBoundingClientRect()` 两两不相交;与「下一步」文字、速度/高度块不相交;中英文各测一次。

## 6. F5:布局编辑器补全(P-03)

这是工作量最大的一块。v4 的编辑器是「自动/自定义」整体二选一的简化版,必须按布局方案 + 控制台方案 §13 重做数据模型和界面。**公众版不得有任何入口。**

### 6.1 数据模型(schema 2,与控制台方案 §13.6 完全一致)

```json
{
  "schema": 2,
  "name": "我的回收",
  "L": [ {"m":"a"}, {"m":"a"}, {"m":"f","w":"prop1"}, {"m":"f","w":"g"}, {"m":"a"} ],
  "R": [ {"m":"a"}, {"m":"a"}, {"m":"a"}, {"m":"a"} ],
  "S": [ 12 个格,结构同 L、R ]
}
```

- 每格:`{m:'a'}` 自动,或 `{m:'f', w:<小部件id>}` 固定。
- **容量**:紧凑左区 L = 5 格,右区 R = **4 格**(第 5 格让给 ABORT;v4 对话框写的是 5 格,要改),控制台总览 S = 12 格。
- 小部件库 15 个:`eng1`(2 格)、`prop1`、`thrust`、`thr`、`g`、`q`、`mach`、`cd`、`heat`、`brk`、`att`、`mass`、`margin`、`eng2`(2 格,SIM)、`prop2`(SIM)。系统小部件 `verdict` 在 t∈\[420,428) 临时覆盖左区最后一格,不可编辑。
- **发动机矩阵 `eng1` 是普通小部件**,占 2 格,可以被移动或替换;不再像 v4 那样把「格 1」锁死。
- v4 现有的 `{mode, left[], right[], S}` 格式只在**读取旧存档时迁移**一次:`mode:'auto'` → 全部 `{m:'a'}`;`custom` → 把 `left/right` 里的小部件 id 逐格转成 `{m:'f',w}`,`'none'` 转成 `{m:'a'}`;迁移后写回新键并不再读旧键。

### 6.2 纯函数(可在 Node 里测试,不依赖 DOM)

- `resolveLayout(layout, t) → {L:[…], R:[…], S:[…]}`:先放所有固定格,再按 `AUTO_SCHEDULE` 给自动格填内容;已被固定格占用的小部件,自动格跳过(同一集合内不重复);2 格小部件占两格;空格保持空白,**不重排其他格**。
- `validate(layout) → {ok, errors[]}`;`serialize(layout) → string`;`parse(string) → {layout, warnings[]}`(见 6.5)。
- `AUTO_SCHEDULE`:紧凑与控制台默认日程按布局方案和控制台方案 §13.4 照抄,窗口左闭右开。紧凑:L1+L2=`eng1` 全程;L3=`prop1` 全程;L4=`g`\[0,150)∪\[330,428);L5=`thr`\[64,92)/`heat`\[330,395)/`brk`\[395,420);R1=`thrust`\[0,156)→`eng2`(2 格)\[156,428);R2=`mach`\[0,156);R3=`q`\[0,156)→`prop2`;R4=`cd`\[0,156)→`margin`。控制台 S1–S12 见控制台方案 §13.4。

### 6.3 校验规则(`validate` 必须全部实现,错误文案走 `L(中,英)`)

| 规则 | 说明 |
| --- | --- |
| 集合内不重复 | 紧凑集合 = L + R;控制台集合 = S;两个集合互不影响 |
| 2 格小部件 | 不能放在区域最后一格;其下一格不能是固定格 |
| 固定优先于自动 | 固定格里的小部件,自动日程不得再显示 |
| 阶段语义小部件 | `thr`、`heat`、`brk` 固定显示时,在无意义阶段**变暗**,不隐藏 |
| 长度 | L=5、R=4、S=12,否则报错 |
| 未知小部件 id | 报错并指出格位 |
| 锁定元素 | 时钟、速度、高度、ABORT、时间轴、小地图、版本/语言切换、总览里的「报警列表」和「GO/NO-GO」**不出现在编辑器里**,也就不可移除 |

### 6.4 编辑器界面(对话框 760×560,草稿制)

1. **入口**:工程版顶栏「布局 (K)」和键 `K`;公众版没有入口,`K` 在公众版无效。控制台模式下入口在顶栏 `⋯` 菜单里(见 5.1)。
2. **顶部切换** `紧凑模式 | 控制台总览`。紧凑显示 L1–L5 与 R1–R4;控制台显示 S1–S12(分左右两列排 S1–S6、S7–S12)。编辑的标签与当前模式不同时允许编辑,并提示「应用后切换到该模式才能看到」。
3. **每格一行**:格名 + `自动 | 固定` 分段按钮 + 小部件下拉(只在「固定」时可选)。已被同集合其他格占用的小部件在下拉里置灰并写明占用的格号。`eng1`、`eng2` 标 `2 格`。
4. **预览示意**随标签切换(紧凑:底部仪表盘示意;控制台:总览 B 行小部件条);**预览阶段选择器**(发射前 / Max-Q / MECO 后 / 再入 / 着陆)对两个标签都有效,选中某阶段就按该阶段的 t 调用 `resolveLayout` 画预览。
5. **草稿制**:所有修改先改草稿,点「应用」才生效,点「取消」丢弃。草稿有错误时「应用」置灰,并在对应格旁显示错误文案。
6. **预设**(下拉或按钮,点击只改草稿):`默认`、`发射`、`回收`、`审阅`。v4 的「发射专注/回收专注/结构气动」改名为这四个。控制台 S 的内容按控制台方案 §13.6 表格;紧凑 L/R 的内容以布局方案 §4 为准;若布局方案没有给出,用下面的默认值并写进偏离表:
   - 发射:L=`eng1`(2)、`prop1`、`g`、`thr`;R=`thrust`、`mach`、`q`、`cd`
   - 回收:L=`eng1`(2)、`prop1`、`g`、`brk`;R=`thrust`、`heat`、`att`、`margin`
   - 审阅:L=`eng1`(2)、`prop1`、`g`、`q`;R=`thrust`、`mach`、`cd`、`margin`
   - 默认:全部自动
7. **我的布局**:「另存为」(取名,最多 5 个,满了提示先删除)、重命名、删除、加载。「恢复默认」回到全自动。
8. **导出/导入**:对话框里有「导出」(显示 JSON 文本框,带「复制」)和「导入」(粘贴 JSON → 校验 → 载入草稿)。**不得把布局放进 URL 哈希。**
9. **编辑时自动暂停仿真**,关闭对话框后恢复到打开前的状态(记住打开前是否在运行,存入 `aether.layout.pause`)。

### 6.5 存储、导入与错误处理

- 存储键:`aether.layout.active`、`aether.layout.saved`(数组,≤5)、`aether.layout.pause`。所有读写 `try/catch`。
- `parse` 支持 schema 2;**也必须支持 schema 1(只有 L、R):导入成功,`S` 取默认全自动,不报错,只给一条提示「已升级旧布局」**。schema 不是 1 或 2、JSON 损坏、字段缺失:返回明确错误文案,不改变当前布局。
- 读取到损坏的存档:回退默认布局,并在对话框里提示一次,不要抛异常。
- 切换模式不会丢失另一个模式的布局;刷新后保持已应用的布局;公众版不受影响。
- 测试钩子 `__test.setLayout(obj)`:接受 schema 1 和 2;失败时**返回/抛出带原因的错误**。再加 `__test.getLayout()` 返回当前**已应用**的 schema 2 对象、`__test.resolve(t)` 返回该 t 下 L/R/S 的小部件 id 数组。

## 附录 A:测试脚本骨架(Python + Playwright)

```python
import asyncio, itertools
from playwright.async_api import async_playwright
F = "file:///path/to/AETHER-9_飞行控制台_v5.html"
TS = [0,6,77,100,150,160,340,395,420,427]
FAULTS = [None, (3,6), (0,390)]          # (发动机编号, 注入时刻)
MODES = ["#public", "#engineering", "#console"]

async def main():
    async with async_playwright() as p:
        b = await p.chromium.launch()
        bad = []
        for mode, fault in itertools.product(MODES, FAULTS):
            pg = await b.new_page(viewport={"width":1440,"height":810})
            errs = []
            pg.on("pageerror", lambda e: errs.append(str(e)))
            pg.on("console", lambda m: errs.append(m.text) if m.type=="error" else None)
            await pg.goto(F + "?test=1" + mode); await pg.wait_for_timeout(500)
            views = range(1,7) if mode == "#console" else [None]
            for v in views:
                if v: await pg.keyboard.press(str(v))
                for t in TS:
                    if fault and t == fault[1]:
                        await pg.evaluate(f"__test.injectFailure({fault[0]},true)")
                    await pg.evaluate(f"__test.setT({t})"); await pg.wait_for_timeout(120)
                dup = await pg.evaluate("""()=>{const m={};document.querySelectorAll('[id]').forEach(e=>m[e.id]=(m[e.id]||0)+1);
                          return Object.keys(m).filter(k=>m[k]>1)}""")
                if dup: errs.append("dup ids: " + ",".join(dup))
            if errs: bad.append((mode, fault, sorted(set(errs))))
            await pg.close()
        print("FAIL" if bad else "PASS", bad)
        await b.close()
asyncio.run(main())
```

注意:`setT` 之后要等 100–200 ms 再取值;故障要在到达对应时刻时注入;每个组合用新页面,避免状态残留。
